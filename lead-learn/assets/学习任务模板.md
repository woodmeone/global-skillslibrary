# 学习任务模板

> 用法：`/recall <AGENT>` + 下面那段。只填 `<AGENT>` 和 `N`，**逐字用，不改写、不缩写**。

---

## 正文（直接复制）

```
/recall <AGENT>

staging 里有 N 篇从收藏抓来的稿子，按你自己的规矩消化：

- 一次全读完，逐篇判断，每一个都要思考，然后结合你自身的知识框架理解
- 辩证的看所有的知识，包括你自己的知识框架以及新的知识
- 值得留的提炼成条目
- 不值得的丢掉，处理完把派单文件里你学完的那一条划掉（**不是删素材真源，见下**）
- 沉淀成自己的长期内容
- 写一篇事件类日记并 ingest

需要看画面用 storyboard 抽帧。
涉及到视频的可以下载下来
需要字幕的可以转录
如果是文章类的，直接看就好

完了告诉我：收了哪几篇归到哪、丢了哪些为什么、有没有跟你已有认识冲突，还有本次你学到了什么（举具体的场景例子）
```

---

## 两处要手动填

| 占位 | 填什么 | 怎么查 |
|---|---|---|
| `<AGENT>` | 目标角色名 | `python scripts/dispatch.py roster` |
| `N` | 篇数 | `python scripts/dispatch.py status` |

**没有 recall 的角色**：把 `/recall <AGENT>` 换成它的 `self.md` 路径，其余照旧。

---

## 为什么不能自己编模板

v1 我编过八步长模板（boot → 读索引 → 读材料 → 逐篇判断 → 写条目 → 索引 → 日记 → 清理），派 `learner-ii` 学 5 篇，**被中断，零产物**：staging 原封不动，longterm 无新文件。

原因：recall 的 SKILL.md 已经规定了完整流程，模板再写一遍就是重复；八步的每一步都在子智能体要自己决定「要不要做」，选项一多就卡死。

**所以模板只回答三件事**：材料在哪、做什么、怎么汇报。流程交给它的 skill。

---

## 一处致命的歧义：「staging 原文」指哪一份

`staging` 这个词在整条链路里出现在**两个完全不同的地方**，一个有删除风险，一个没有：

| 位置 | 是什么 | 能不能删 |
|---|---|---|
| `$LEAD_LEARN_HOME/.favorites-out/longterm-staging/*.staged.md` | **抓取侧素材真源**。mp4 清掉之后它是唯一兜底，链接失效就靠它 | **一份都不许删** |
| `lead/longterm/dispatch/<agent>_staging.md` | **派单队列**，待办清单 | 学完划掉对应条目；全学完才删整份 |

原模板写的「处理完删 staging 原文」，指的是后者。**2026-11-24 实测里三个子智能体都读成了前者**（量量甚至已经写好日记准备删），靠中途追加硬规矩才拦住。

所以正文里那句话已改成「把派单文件里你学完的那一条划掉」，并且派单文件头部也加了同样的提示。

**可迁移的教训**：给子智能体的提示词里，**同一个词指两样东西就是隐患**。子智能体看不到你的上下文，它只会挑那个更显著的读法。写提示词时要问一句「这个词在他那边的盘面上指向哪个路径」，指不出来就换词。

## 工具映射

模板里「需要字幕的可以转录」这类句子怎么落：

| 材料情况 | 用什么 |
|---|---|
| 已有文字稿 | 直接读派单里的链接和 staging |
| 需要字幕 | `asr-subtitle` 的 `transcribe.py` |
| 需要下载 | `media-downloader` 的 `download.py`，带 `--cookies` |
| 需要看画面 | `dsh-video-storyboard` 的 `storyboard.mjs` |
| 抖音 | 本 skill 的 `scripts/douyin_dl.py`（yt-dlp 无抖音通道） |

凭据一律走 CookieCloud 导出的 cookie 文件，不用本地浏览器：
`$LEAD_LEARN_HOME/.favorites-out/{bilibili,douyin}-cookies.txt`
