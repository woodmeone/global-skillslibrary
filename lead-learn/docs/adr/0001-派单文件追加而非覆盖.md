# ADR-0001 · 派单文件用追加而非覆盖

- 日期：2026-11-24
- 状态：已采纳

## 背景

`dispatch.py apply` 原先对每个 agent 的 `<agent>_staging.md` 做整份 `write_text`。
第二轮派单时，上一轮没学完的条目会被静默抹掉。

2026-11-24 实测复现：先 apply 一轮（2 条），再 apply 一轮（1 条），
结果文件里只剩本轮的 1 条，上一轮 2 条消失，不报错、不留痕。

## 决策与取舍

**改为追加**：`path.exists()` 时把旧正文取出、拼在新正文前，中间加
`<!-- 以下为 … 新派 -->` 分隔，并把 `count` 重算成总待消化数。

放弃的方案：

| 方案 | 为什么不选 |
|---|---|
| 每轮一个独立文件（`<agent>_staging-2.md`） | `status` 的「派单文件数 = 还没交活的 agent 数」就不成立了，进度指示器失真 |
| 覆盖但先在旧文件里报警 | 报警没人看，派单本身已经没了 |
| 覆盖前 `git mv` 归档 | 派单目录不在 git 里，且归档多了没人清 |

## 后果

- **好**：上一轮的活不会消失；`count` 自动反映真实待消化数；`status` 能报漂移。
- **坏**：文件会越来越长。目前靠「学完划掉条目」控制，若某 agent 长期不交活，
  文件会不断堆积——这是**希望的失败方向**（堆积可见，丢失不可见）。
- **需要配合**：`_pending_count()` 数 `## N.` 条目，划掉的要写成 `## ~~N.` 才不计入。
