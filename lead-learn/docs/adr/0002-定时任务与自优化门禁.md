# ADR-0002 · 定时任务每夜跑 + 自优化必须过三道闸

- 日期：2026-11-24
- 状态：已采纳

## 背景

YG 要求：①定时任务自动学习 ②跑完发现不合理可以优化 skill。

实测两个数决定了设计：

1. **收藏速度 1.8 条/天**（抖音 40 条收藏跨 22 天）。每晚跑一次，七成以上夜晚 0 新增。
2. **空跑不烧钱**：`cmd_run` 发现 `detect_new()` 为空会打印「没有新增，跳过」直接退出。
3. **但无人值守的自改动是真风险**：`lead-learn` 原本没有 `.git`，
   改坏一个语法错，第二天整条链路哑掉且无人知晓。

## 决策与取舍

### 决策一：定时任务每夜跑，但只跑到「派单」，不自动派子智能体

- 夜里跑：`bili_grab3.py` → `favorites.py grab douyin` → `pipeline.py run --limit 20` → `pipeline.py stage` → `pipeline.py clean`
- **不自动开子智能体**：分流是判断，判断需要人（或有人监督的模型）。
  半夜自动派单，等于让一堆 agent 在没有把关的情况下吃材料，且没人看它判得对不对。
- 早上你看一眼 `dispatch.py list`，觉得该派再派。

放弃的方案：

| 方案 | 为什么不选 |
|---|---|
| 每周跑一次 | 热点类内容过夜就凉，且抓取窗口已提到 100，日频也不会积压 |
| 每晚跑 + 自动派子智能体 | 分流判断无人把关，代价是 agent 拿不相关的东西消化，比不派更糟 |
| 用 cron 而不用 dsh schedule | 拿不到 dsh 的会话上下文与日志 |

### 决策二：自优化必须过三道闸，缺一不提交

自优化 = 跑完生成问题报告 → 判断要不要改 → 改 → 验 → 提交。

**G1 前置**
- 必须先在 `docs/issue-*.md` 立 Issue（or 追加到已有 Issue 的票）
- 必须是**干净上下文**：自优化不能在自己刚跑完的那次会话里顺手改
  （那次会话有偏好残留，会偏向「证明自己刚才做对了」）

**G2 门禁（顺序固定，不通过不进下一步）**
1. `python -m pytest tests/ -q` 全绿
2. 三个冒烟命令全 exit 0：
   `dispatch.py status` / `health.py` / `pipeline.py status`
3. `git diff` 里不许出现：`SKILL.md` 的 `name` / `description`、
   `paths.py` 的路径常量、`assets/学习任务模板.md`

**G3 回滚**
- 任一闸不过 → `git revert` 或 `git checkout -- <file>`，**并把失败写进 Issue 评论**
- 允许自动 revert 的条件：改动能被 `git revert` 干净还原（即已 commit 且无未提交冲突）

## 为什么允许自动改（而不是只出报告）

YG 明确要求「允许自动改，但必须走 git-native-sop 规范，和测试」。

所以边界是：**自动改的自由度 = 测试能覆盖的范围**。
- `scripts/` 里的逻辑改动 → 可以自动改（有回归测试兜底）
- `SKILL.md` 的触发描述 → 不许自动改（改了触发 skill 目录刷新，改错整个 skill 消失）
- 记忆区（`~/.midnight/recall`）→ 绝不自动改

## 后果

- **好**：夜里没人也能把材料备好；坏改动有 git 兜底、有测试拦、有 Issue 留痕。
- **坏**：测试覆盖不到的改动（比如抓取选择器变了）仍会漏网。
  缓解：`health.py` 会报「收藏数据 N 小时前」不新鲜，这是选择器失效的早期信号。
- **需要维护**：Issue 会越积越多。规则：一个 Issue 全票完成后 close，
  新问题开新 Issue，不在已 close 的 Issue 上续。
