# 手册配图：画什么、怎么画

## 先判断：这张图该不该画

**截图能表达的，不要画图。** 截图说"按钮在这"，图说"你在流程的哪一格"。两者不重叠。

值得画图的四种信号：

| 信号 | 图类型 | 例 |
|---|---|---|
| 读者不知道自己在整个流程的哪里 | 流程条 | 买家从进站到收货的五个步骤 |
| 一个实体有多种状态、转错就出问题 | 状态机 | 开户：草稿→审核中→已激活，另有补件/拒绝/暂停 |
| 一个东西被拆成多个，各管各的 | 结构图 | 一个主单拆成多个子单，各自履约结算 |
| 一件事两方分工，用户找不到按钮 | 对照梯 | 商户发起 / 平台审核，六个环节 |
| 钱或物的一步步转化 | 流向条 | 付款→清算→冻结→可回款→在途→到账 |

**别为了"配图"而画图。** 一张"系统架构图"放在操作手册里没用——读者不关心技术架构，只关心自己下一步点哪。

## 画图前的三个决定

### 1. 画布高度先定死

`Canvas(h_cm=8.0)` 里的高度决定纵向可用空间（ymax ≈ 100 × h / 15.5）。

**先算纵向分带，再往里放东西**：

```
h_cm=9.8  →  ymax ≈ 63
  3      标题
  12–20  主干四个状态
  24     回环走线
  32–40  下方两个分支
  47     底部要点
```

边画边凑必然重叠。这个顺序反了要重画三遍。

### 2. 主干走横，分支走上下

主干横排（草稿→审核中→已激活），分支向下（待补件）或向上（回环）。

分支线**不要穿过别的方框**。宁可绕远：从底部下去，横向走空档，再折回来。

### 3. 标签放在框外，不压在线上

`arrow(label=...)` 的标签默认在两点中点，很容易压在连线或方框上。两个解法：

```python
# 解法 A：用 label_offset 挪开
cv.arrow(p1, p2, label="提交审核", label_offset=(0, -2.5))

# 解法 B（更稳）：不用 arrow 的 label，单独用 sub() 放在预留的带位
cv.arrow((x1, cy), (x2, cy))
cv.sub((x1+x2)/2, cy - 3.0, "提交审核", fs=8, color=GRAY)
```

解法 B 更好——位置完全可控，不会被 bbox 推来推去。

## 常见排版事故

| 现象 | 原因 | 修法 |
|---|---|---|
| 文字压住方框 | y 值落在框内 | 算准框的上下边界，注释放框外 |
| 箭头"断了" | 标签白底盖住连线 | 标签挪到线的一侧 |
| 图被裁掉一半 | 画布高度不够 | 加大 `h_cm`，或减少带位 |
| 分支线穿过别的框 | 直线连接 | 改折线（三段 arrow）或加 `rad` 弧度 |
| 容器标签压住第一行内容 | 标签写在边上 | `container()` 已把标签放左上内角 |
| 图中文字太小看不清 | dpi 太低或画布太宽 | dpi=300 且贴图用满版宽 15.5cm |

## 贴进文档

```python
import docx_kit
docx_kit.FIGS = Path("docs/manual-figures")

add_figure(doc, "fig-A-roles.png", "图 1-1　三类使用者与各自的权限边界")
```

`add_figure` 按满版宽（15.5cm）贴出，不切分——逻辑图比例本来就宽，切开会断义。

**关键**：示意图必须满版宽。缩小到 12cm 会导致图内 8pt 字变成 5pt，读者得放大看，图就白画了。

## 两个库不能裸 * 导入

`diagram_kit` 和 `docx_kit` 都有 `ACCENT`、`GRAY`、`BLUE` 等颜色常量，但类型不同：

- `docx_kit.ACCENT` 是 `RGBColor` 对象（给 python-docx 用）
- `diagram_kit.ACCENT` 是 `"#0F6B4F"` 字符串（给 matplotlib 用）

同时用会出现：

```
ValueError: RGBColor(0x0f, 0x6b, 0x4f) is not a valid value for color
```

**解法**：`diagram_kit` 提供了 `DK_` 前缀的无歧义别名。

```python
from docx_kit import *
from diagram_kit import Canvas, DK_ACCENT, DK_GRAY, DK_AMBER, DK_BLUE, DK_RED, DK_LINE
# 画图时统一用 DK_ 前缀，写文档时用 docx_kit 的裸名
```

## 与正文的配合

图不是装饰。每张图前后都要有一句话把它和上下文绑起来：

```markdown
本手册只覆盖下面三块里的第一块。看懂这张图，你就知道遇到什么事该找谁。
[图 A]
你作为买家，全程不需要账号，只接触自己的订单。订单出问题先找卖家。
```

三句话结构：**引出（这张图解决什么疑问）→ 图 → 收束（所以你要做什么）**。

## 图号与命名

- 图号 `图 <章>-<序>`，章内连续，跨章重置
- 文件命名 `fig-<字母>-<语义>.png`（`fig-A-roles.png`），字母按在文档中出现的顺序
- 同一张图用在不同手册时，图号可以不同，但文件名共用
