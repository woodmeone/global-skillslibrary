# 手册结构与写法

## 章节骨架

按角色各写一份，每份都套这个骨架。**顺序不要换**——读者是按"我要干什么"线性找的。

```
封面      角色名 / 一句话功能概括 / 适用对象 · 入口地址 · 版本
零        先看两张图：角色边界 + 主线流程（图，不是文字）
一        进入方式（登录 or 直接访问）
二        登录与后台导览（仅登录角色）
三        核心业务流第一步（如开户 / 浏览）
四        核心业务流第二步（如店铺设置 / 加购）
...       每个业务环节一章
N-2       数据查看（订单 / 资金 / 报表）
N-1       不可逆操作清单（仅管理员）
N         常见问题
```

**「零」这一节别省。** 原来直接从"一、进入商城"开始，读者不知道后面还有什么、自己在整条链的哪个位置。补上两张图 + 两句话，读者立刻有坐标系。

写法：

```markdown
零、先看两张图

本手册只覆盖下面三块里的第一块。看懂这张图，你就知道遇到什么事该找谁、该看哪份文档。
[图 0-1 角色边界]
你作为买家，全程不需要账号，只接触自己的订单。订单出问题先找卖家。
接下来这张图是你从进站到收货的完整路径，本手册后续章节就按它展开：
[图 0-2 主线流程]
记住最关键的一点：……
```

三句话结构：**引出（解决什么疑问）→ 图 → 收束（所以你要做什么）**。

## 每章的内部结构

固定四件套，缺一样读者就会卡：

```markdown
## 一、章节名

一句话说清这一章解决什么问题。

### 1.1 字段/操作清单
表格列出所有输入项或可点项，三列：字段 | 要求 | 说明

### 1.2 操作步骤
1. 点哪里
2. 填什么
3. 看到什么反馈

![图 1-1　说明文字](shot.jpg)

### 1.3 状态与异常
状态机表格，或"什么情况下会失败、怎么办"
```

## 字段表怎么写

三列，第三列是**读者真正需要的**——为什么这么填，填错什么后果：

| 字段 | 要求 | 说明 |
|---|---|---|
| 统一社会信用代码 | 必填，18 位 | 营业执照上的 USCC |
| 账户名 | 必填 | **必须与企业法定名称一致，否则回款失败** |
| EZ WAY 实名手机 | 09 开头 10 位 | 海关据此推播，未实名无法清关 |

不要写成"统一社会信用代码：企业信用代码"——同义反复，零信息量。

## 步骤怎么写

每步只做一件事，动词开头，说清"点哪里"和"看到什么"：

✅ 点「保存开户申请」，此时状态为「草稿」。
❌ 填写完信息后保存。

## 图注规范

`图 <章>-<序>　<说明>`，中间用全角空格。说明写"这张图在佐证什么"，不是"这是什么页面"：

✅ 图 3-2　商户详情页（商户视角）：主体资料与资金三项
❌ 图 3-2　商户详情页截图

## 常见问题

**只写读者踩过的坑**，不写"如何联系我们"这种废话。判断标准：这个问题会不会让人卡住不动。

好的问题长这样：

- 注册完为什么不能上架商品？（预期落差）
- 为什么看不到某个菜单？（以为故障，其实是权限设计）
- 按钮点了没反应 / 提示某错误？（正面阻塞）
- 钱什么时候能提？（资金焦虑）

每个答案给出**原因 + 动作**，不要只说"请联系管理员"。

## 语言

- 界面语言跟随产品（繁中界面就写繁中操作词）
- 正文语言跟随读者（向用户确认）
- 操作词加粗或换色，与界面文案完全一致，包括标点
- 不用"您"，用"你"——操作手册不是客服话术

## 不可逆操作清单（管理员手册必写）

这是整份文档最有价值的一节。表格三列：

| 操作 | 影响 | 执行前必须核对 |
|---|---|---|
| 审核通过并开户 | 创建收款账户，商户立刻获得收款能力 | 企业名称 = 收款账户名；USCC 18 位正确 |
| 审核通过回款 | 资金离开平台清算，出账 | 试算平衡；锁汇汇率；关联子单真实 |
| 跳过观察期放款 | 提前放款，绕过售后观察期 | 签收是否确已发生；是否接受售后风险 |

写这一节时问自己：**这个操作做错了，多久能发现？** 越难发现的越要写进核对项。
